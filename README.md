# Inventory repositioning datasets

50 synthetic datasets generated by running the supplied Java code: 10 each for Berlin (10 hubs), Vienna (20), London (50), Paris (100), and Milan (200).

## Parameters

As confirmed, i = j = hub count; m = 3 external suppliers; k = 1 part type. The i and j indices represent the same hubs in supplying/receiving roles. External m sites are additional suppliers. City names are labels only; there are no geographic coordinates or actual city shipping costs.

| City | Hubs | Datasets | Seeds / instance serial numbers |
|---|---:|---:|---|
| berlin | 10 | 10 | 1001–1010 |
| vienna | 20 | 10 | 2001–2010 |
| london | 50 | 10 | 3001–3010 |
| paris | 100 | 10 | 4001–4010 |
| milan | 200 | 10 | 5001–5010 |

Each city folder contains ten Excel workbooks and ten instance folders. Each instance folder contains four CSV tables: Eik (excess), Njk (needed), Bmjk (external-supplier costs), and Cijk (hub-to-hub costs). dataset_index.csv maps each replicate to its seed and output files.

Generation rules are unchanged: exactly one of excess/needed is positive at each hub; positive quantities are 20–149; off-diagonal external-supplier costs are 75–174 and hub-to-hub costs are 50–149. All diagonal costs are zero, including the original rule for matching m and j indices even though m sites are separate. Costs are directed and need not be symmetric. Numeric Excel entries remain text, as in the original program. No optimization solver was run, and feasibility/optimality is not guaranteed by generation.

## Code and reproduction

source/Main_original.java is the supplied file, unchanged. source/Main.java contains only execution/portability adjustments: a configurable output directory, platform-native path separators, one shared input scanner for batch input, and workbook resource cleanup. The random-number generator, random draw order, ranges, and table generation are unchanged.

Java dependencies are included in deps/. With Java 17+ and Python 3 installed, run:

    python3 run_datasets.py

This regenerates outputs with the same seeds. It overwrites matching output files. generation.log in each city folder records the batch execution. Four incomplete workbook exports were detected during validation and regenerated with identical seeds before final verification. The wrapper checks for incomplete workbook exports and retries once. Batch timings refer to the initial batch and exclude these individual retries. Timings include Java startup and file export; they are not solver timings.

Optional verification requires openpyxl:

    python3 validate_datasets.py

validation.json records checks of all row counts, identifiers, bounds, zero diagonals, excess/needed exclusivity, distinctness, and exact agreement between Excel cells and CSVs.
